# Animation・Animator 深掘り 課題

**DemoPlayer（お手本のプレイヤーのコピー）を使って、「当たる瞬間」「切り替わり」「手の置き場所」を自分で決められること**が今週のゴールです。
動いたかどうかに加えて、**「なぜそのフレーム・その値にしたのか」を説明できるか**を見ます。

**使用シーン**：`Assets/Application/Week01-Animation/Week01-Animation_Start.unity`

> 先週欠席した人も `_Start` シーンから入れば合流できます。
> 触ってよいのは `Week01-Animation/` の中だけです。お手本（`_DemoGame/`）は編集しないでください。

## 1 (必須) 別のモーションで、振り下ろした瞬間に当てる

---

授業では `Enemy_Attack_1` に Animation Event を置きました。今回は **RPG Animations Pack FREE の別の攻撃モーション**に差し替えてください。
モーションが変わると、**当たる瞬間も変わります。** 自分でコマ送りして、イベントの位置を決め直してください。

条件

```csharp
・授業で使っていない攻撃モーションを使う（例：One Hand Up/Attack_A や Attack_B の中から1つ）
・Rig が Humanoid / Copy From Other Avatar になっていることを確認する
・Clip を .anim にコピーして Week01-Animation/Animations/ に置き、AC_Player の Attack ステートに入れる
・Animation Event で PlayerAttack の判定（ApplyDamage）を呼ぶ。ボタンを押した瞬間には呼ばない
・判定の球（DebugShapes の表示）が、杖が振り下ろされた瞬間に出る
```

提出方法

攻撃を**3回以上**出し、**判定の球が振り下ろしの瞬間に出ている**ことがわかる動画と、
Animation ウィンドウで**イベントを置いたフレーム**が映ったスクリーンショットをslackに提出してください

## 2 (必須) 歩き → 走りの切り替わりをなめらかにする

---

今の DemoPlayer は、Shift を押した瞬間に Speed が 2 から 5 へ飛ぶので、**歩きから走りへ1フレームで切り替わります。**
Blend Tree はそのままで、**送る値の側**を直して、切り替わりがなめらかになるようにしてください。

条件

```csharp
・AC_Player の Blend Tree（閾値 0 / 2 / 5）は変えない
・CharacterVisual に dampTime 付きで SetFloat できる入口を足し、PlayerAnimation から使う
・待機 → 歩き → 走り → 歩き → 待機 で、Animator の Speed が飛ばずに変わる
・攻撃は今までどおり、押した瞬間に出る（Speed の変更で遅れない）
```

提出方法

**待機 → 歩き → 走り → 歩き → 待機**と動かす様子と、**プレイ中の Animator ウィンドウの Speed の値**が一緒に映った動画を、
**直す前と直した後の2本**slackに提出してください

## 3 (推奨) 走りながら上半身だけで攻撃する

---

今の `AC_Player` は Base Layer だけなので、走りながら攻撃すると**足が止まります。**
**走っている最中に攻撃しても、足が走りのまま動き続ける**ようにしてください。

条件

```csharp
・Avatar Mask で上半身だけを有効にしたものを作り、Week01-Animation/Animations/ に置く
・AC_Player に上半身用の Layer を追加し、そこに攻撃を置く
・課題1の Animation Event は、上半身の Layer で再生しても呼ばれる
・止まっているときの攻撃は、今までどおり全身で攻撃してもよい（しなくてもよい）
```

提出方法

**走りながら攻撃して、足が走りのまま動き続けている**ことがわかる動画をslackに提出してください

## 4 (推奨) 手を伸ばして押すスイッチを作る

---

篝火や灯火と同じように、**E を押すと右腕が伸びて、手が届いた瞬間に反応する**スイッチを新しく作ってください。
押すモーションは使いません。**DemoPlayer の `Rig_Reach`（右腕の IK）をそのまま使います。**

条件

```csharp
・スイッチは Cube で可。IInteractable を実装した新しいスクリプトを作る（namespace は Week01）
・Interact の中で PlayerStaffReach.ReachOrRun を使い、手を置く位置はスイッチの表面にする
・手が届いた瞬間（ReachOrRun に渡した処理が呼ばれたとき）に、スイッチの色が変わる
・押したあとはもう一度押せない、または押すたびに切り替わる（どちらかを選ぶ）
・壁の高い位置・低い位置にも1つずつ置き、どちらでも手が表面に届く
```

提出方法

高い位置と低い位置のスイッチを押す様子を**横から**映した動画をslackに提出してください

## 5 (応用) 坂道や段差で、足を地面に合わせる

---

モーションは平らな地面の上で作られています。坂道や階段の上に立たせると、**片足が宙に浮いたり、地面にめり込んだり**します。
**坂道・段差の上に立ったときに、両足がちゃんと地面についている**状態にしてください。

何が「ちゃんとついている」なのかは、自分で決めてください。

条件

```csharp
・坂道（傾けた Cube）と段差（階段状に並べた Cube）を用意する
・その上で待機しているときに、両足が地面から浮いて見えない／めり込んで見えない
・歩き出したときに、足の動きが不自然にならない（止まるときと動くときの切り替えも含めて）
・箱押し（Rig_Hands）と、手を伸ばす動き（Rig_Reach）を壊さない
・「どうなっていたら足がついていると言えるか」を、自分の言葉で定義して提出時に書く
```

提出方法

坂道と段差の上で**待機・歩き**をしている様子を、**足元が見える角度**で映した動画と、上で決めた定義（2〜3 行）をslackに提出してください

ヒント

```csharp
・Rig_Hands と同じように、脚の Two Bone IK を入れた Rig を足す（Thigh → Leg → Foot）
    or
・AC_Player の IK Pass をオンにして、OnAnimatorIK で AvatarIKGoal.LeftFoot / RightFoot を動かす
・どちらでも、足の上から下へ Physics.Raycast を飛ばし、当たった位置に足の目標を置く
・腰（Hips）を下げないと、低い側の足が届かない。体全体をどれだけ下げるか
```
